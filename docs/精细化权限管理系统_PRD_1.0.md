# 精细化权限管理系统 PRD 1.0

## 1.0 文档概述

### 1.1 背景
随着CDP应用系统业务逻辑日趋复杂，数据敏感性增强，现有的粗粒度权限管理已无法满足安全、合规与精细化运营的需求。系统需要一套全新的、支持功能级和字段级的精细化权限管理系统，以确保不同岗位的用户只能访问其职责范围内的功能与数据。

### 1.2 产品目标
- **核心目标**: 构建一套基于角色 (RBAC) 的精细化权限管理系统，实现对用户操作功能和访问数据字段的双重控制。
- **管理目标**: 为系统管理员提供一个清晰、高效、不易出错的图形化配置界面，用于管理所有角色与权限。
- **安全目标**: 遵循最小权限和默认拒绝原则，从后端强制执行所有权限规则，杜绝越权风险。

### 1.3 成功指标
- **效率**: 管理员在 5 分钟内可以完成一个新角色的创建、功能授权和核心字段授权。
- **准确性**: 系统上线后，因权限配置错误导致的数据安全事件数量为 0。
- **灵活性**: 新增业务模块或数据字段时，无需修改代码，仅通过配置即可纳入权限管理。

## 2.0 目标用户与场景

### 2.1 目标用户
**系统管理员 (System Administrator)**
- 具备基本的计算机操作能力
- 理解公司业务流程和岗位职责划分
- 负责系统的权限配置和用户管理

### 2.2 用户痛点
1. 现有权限配置方式复杂且不直观，容易出错
2. 无法对敏感数据的可见性进行精确控制，存在数据泄露风险
3. 每次业务调整，都需要开发人员介入修改权限，效率低下

### 2.3 使用场景
**场景一：新员工入职**
管理员需要为一个新入职的"初级销售"快速分配一个预设好的角色，使其立即拥有工作所需的最小权限。

**场景二：业务流程调整**
公司决定"销售经理"角色也需要能看到客户的"信用评级"字段，管理员需要能快速找到对应角色的权限配置并精准地开启该字段的读取权限。

## 3.0 用户故事 (User Stories)

### 3.1 角色管理
- US-1: 作为一名系统管理员，我希望能在一个集中的界面创建、查看、编辑和删除角色，以便于我对系统的所有岗位职责进行统一管理。
- US-2: 作为一名系统管理员，我希望在编辑角色时，能以业务模块分组的方式清晰地看到所有功能和字段权限，并通过勾选的方式为角色授权，从而避免遗漏和错配。
- US-3: 作为一名系统管理员，我希望能复制一个已有的角色来创建一个新角色，以便在处理职责相似的岗位时能大大提高配置效率。

### 3.2 用户权限管理
- US-4: 作为一名系统管理员，我希望在用户管理页面能为指定用户绑定一个或多个角色，以便快速完成对用户的授权。
- US-5: 作为一名系统管理员，我希望所有的权限修改操作都有安全的校验和确认机制，以防止因误操作导致严重的安全问题。

## 4.0 功能性需求 (Functional Requirements)

### 4.1 角色管理模块

#### 4.1.1 角色列表视图
- 以列表形式展示所有角色，并显示角色名称和描述
- 提供搜索功能，可按角色名称快速筛选
- 列表上方应有"新建角色"按钮
- 每个角色条目后应有"编辑"、"复制"、"删除"操作按钮

#### 4.1.2 新建/编辑角色
- 以左右分栏布局展示。左侧为角色列表，右侧为当前选中角色的权限配置面板
- 右侧面板顶部显示角色名和描述的输入框
- 右侧面板下方为权限配置区

#### 4.1.3 权限配置面板
- 权限项必须按业务模块（如"客户管理"、"合同管理"）进行分组，使用折叠面板 (Accordion) 或选项卡 (Tabs) 控件
- 每个业务模块下，分为"功能权限"和"字段权限"两个部分
- 功能权限：以复选框列表或树状结构展示，支持父节点全选/全不选
- 字段权限：提供一个"配置字段权限"的入口按钮。点击后，弹出一个模态框 (Modal)
- 权限项来源：系统自动扫描项目代码生成权限清单，确保与实际功能一致
- 权限同步状态：显示权限配置与项目代码的同步状态，标识过期或新增的权限项

#### 4.1.4 字段权限配置模态框
- 以表格形式列出该资源下的所有字段
- 表格包含列：字段名、字段描述、查看权限(复选框)、编辑权限(复选框)
- 逻辑要求：勾选"编辑"权限时，必须自动勾选"查看"权限。取消"查看"权限时，必须自动取消"编辑"权限
- 表头提供列级别的全选/全不选功能

#### 4.1.5 保存与删除
- 所有权限修改后，需要点击"保存"按钮才生效
- 删除角色前，必须有二次确认弹窗，提示风险
- 保存时自动检查权限配置与项目代码的同步状态，提示可能存在的不一致问题

### 4.2 用户管理模块

#### 4.2.1 用户列表视图
- 以表格形式展示用户列表，包含用户名、邮箱、已分配角色等信息

#### 4.2.2 分配角色
- 在编辑用户时，提供分配角色的功能
- 推荐使用双栏穿梭框 (Transfer) 或多选下拉框 (Multi-select Dropdown) 来为用户绑定一个或多个角色

### 4.3 权限校验逻辑

#### 4.3.1 API 接口保护
- 所有 API 接口都必须经过权限校验中间件，检查用户是否有所需的功能权限。无权则返回 403 Forbidden

#### 4.3.2 数据读取过滤
- 对于返回数据的 GET 请求，后端服务必须根据用户的字段级"查看"权限，对查询出的数据进行过滤，移除用户无权查看的字段

#### 4.3.3 数据写入校验
- 对于修改数据的 POST/PUT 请求，后端服务必须校验请求体中的每一个字段，如果包含用户无权"编辑"的字段，则应拒绝该请求或忽略对该字段的修改

## 5.0 非功能性需求

### 5.1 安全性
- 严格遵循"默认拒绝"原则，未明确授权的权限都应被禁止
- 所有权限校验必须在后端强制执行，前端仅做界面展示

### 5.2 性能
- 用户登录时，应将其权限集合缓存（如使用 Redis），避免每次 API 请求都查询数据库，确保权限校验的响应时间 < 50ms

### 5.3 易用性
- 界面设计直观，术语清晰，减少管理员的学习成本
- 关键操作应有明确的反馈提示（如"保存成功"）

## 7.0 当前系统分析

### 7.1 现有权限结构
CDP系统当前采用多租户架构，包含以下权限层级：

1. **超级管理员**: 系统最高权限，可以访问管理后台所有功能
2. **组织管理员**: 组织级别的管理员，可以管理组织内的成员和设置
3. **普通成员**: 组织内的一般用户，根据角色分配不同的功能权限

### 7.2 现有限制
1. **权限粒度粗**: 当前权限控制仅到页面级别，无法控制具体字段的访问
2. **配置复杂**: 权限配置分散在不同页面，缺乏统一管理界面
3. **扩展性差**: 新增权限需要开发人员修改代码

### 7.3 权限映射实现
基于项目现有架构，可以通过以下方式实现权限与项目的自动同步：
1. **路由扫描**: 利用React Router配置自动生成页面级功能权限
   - 扫描client/App.tsx中的路由配置，提取如"/users"、"/ai-marketing-strategies"等页面权限
2. **组件标记**: 通过高阶组件或自定义Hook标记操作级权限
   - 在组件中使用权限标记，如"canCreateStrategy"、"canEditUser"等
3. **类型提取**: 利用TypeScript的类型系统自动提取数据模型字段
   - 解析shared/userData.ts等文件中的User接口，提取fullName、contactInfo等字段权限
4. **构建集成**: 在Vite构建过程中集成权限验证步骤

### 7.4 权限配置同步机制
为确保权限配置与项目代码保持一致，将实施以下机制：
1. **自动扫描**: 构建时自动扫描项目代码，生成最新的权限清单
2. **差异检测**: 对比现有权限配置与代码中的实际权限点，识别新增、删除或修改的权限
3. **配置更新**: 提供工具自动更新权限配置或生成更新建议
4. **版本控制**: 对权限配置进行版本管理，支持回滚操作

### 7.5 技术架构适配
系统采用React + TypeScript + Tailwind CSS技术栈，具备良好的组件化能力，适合实现精细化权限管理界面。

## 9.0 权限映射与同步机制

### 9.1 功能权限自动发现
系统将自动扫描项目中的路由和页面组件，生成功能权限清单：
- 基于React Router的路由配置自动提取页面级权限（如"/users"、"/ai-marketing-strategies"等）
- 通过组件标记识别按钮级和操作级权限（如"创建策略"、"编辑用户"等）
- 支持手动注册特殊权限点（如导出数据、批量操作等）

### 9.2 字段权限映射
建立数据模型与权限系统的映射关系：
- 通过TypeScript接口定义自动提取字段信息（如User接口中的fullName、contactInfo等字段）
- 支持为敏感字段添加权限标记（如creditRating、salary等敏感字段）
- 提供字段权限配置的可视化界面

### 9.3 权限同步机制
确保权限配置与项目代码保持同步：
- 构建时自动校验权限配置的有效性
- 提供权限差异检测和修复工具
- 支持权限配置的版本管理和回滚
- 定期扫描项目代码更新权限清单

## 12.0 名词解释

- **RBAC**: Role-Based Access Control，基于角色的访问控制
- **功能权限**: 对系统操作行为的许可，如访问页面、点击按钮、调用接口
- **字段权限**: 对数据记录中具体字段的读取或修改的许可
