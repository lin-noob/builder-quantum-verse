## 页面目标与边界
- 构建仅前端原型页面（纯 Mock 数据），用于管理企业层四类注册表：Entities、Capabilities、Rules、Events。
- 明确只读定位：强调“被引用关系”，不做流程编排、不做业务模型编辑、不配置 Agent 行为。
- 页面提示这是企业事实层，资产可被业务模型与 Agent 引用。

## 技术栈与文件结构
- 技术：React + TypeScript，复用项目内现有 UI 组件（如 Button、Card、ScrollArea、Modal）与样式；若不可用则使用基础 HTML/CSS。
- 新增页面：client/pages/EnterpriseRegistry.tsx（单页组件）。
- 路由集成：在现有路由文件（如 client/admin/AdminApp.tsx 或 client/config/staticRoutes.tsx）中注册“/enterprise/registry”。

## 数据模型（Mock）定义
- Entity：{id, name, type: "Master"|"Transaction"|"Event", description, referencedBy: {models: string[], agents: string[]}}
- Capability：{id, name, description, inputEntityId, outputEntityId, risk: "Low"|"Medium"|"High", callableByAgent: boolean}
- Rule：{id, name, ruleType: "合规"|"财务"|"风控", severity: "Info"|"Blocking", scope: "Entity"|"Capability"|"Agent", referencedCount: number, description}
- Event：{id, name, triggerEntityId, condition, subscribableByAgent: boolean, description}
- 统一的 registryId：每类注册表提供一个 registry_id（如 "entity_registry" 等），JSON 预览中展示。

## UI 结构与组件
- 顶部 Header：标题“Enterprise Registry”、副标题“Unified Enterprise Digital Foundation”。右侧两个按钮：切换设计模式（仅 UI）、查看引用关系总览（打开只读总览）。
- 左侧 Sidebar：四个固定入口（Entities/Capabilities/Rules/Events），点击切换中间主视图。
- 中间主视图：
  - Entities：卡片列出 name、type 标签、描述、被引用数量（业务模型/Agent），点击在右侧显示详情。
  - Capabilities：表格或卡片列出 name、自然语言描述、输入实体、输出实体、风险等级、是否可被 Agent 直接调用。
  - Rules：卡片列出 name、规则类型、严重级别、作用范围、被引用次数。
  - Events：卡片列出 name、触发实体、触发条件、是否可被 Agent 订阅。
- 右侧详情面板（只读）：显示选中项的基本信息（名称、类型、描述）与被引用关系（被哪些业务模型引用、被哪些 Agent 使用）。
- 底部 JSON 预览（只读）：根据当前 Registry 类型展示对应 JSON（entity_registry.json 等），包含 registry_id，明确为企业级资产，不含业务模型或 Agent 定义（仅引用信息如名称或计数）。

## 交互逻辑
- 设计模式开关：useState 管理 designMode，仅用于显示“新增/编辑”按钮（按钮无保存逻辑）。
- Sidebar 切换：useState 管理 activeRegistry；切换后主视图加载对应 Mock 列表。
- 选中项：useState 管理 selectedItem；点击主视图项时在右侧详情面板展示。
- 引用关系总览：点击按钮打开 Modal，聚合显示各 Registry 的被引用统计（只读）。

## JSON 预览生成
- 将当前 Registry 的 Mock 数据序列化为 JSON，结构为：{ registry_id, assets: [...] }。
- 序列化时隐藏业务模型与 Agent 的结构定义，仅保留引用名称列表或计数，确保“明确是企业级资产”。

## 无障碍与风格
- 白底、卡片式、企业级 SaaS 风格；卡片阴影与分隔线轻量化。
- 提供清晰标签与只读提示；采用一致的字号与间距体系。

## 路由与集成
- 在现有路由中注册“Enterprise Registry”菜单与路径，归类到企业层/系统设置区域（不与业务模型编辑或 Agent 配置混合）。

## 验证与交付

- 代码组织：单文件或按组件拆分（Header、Sidebar、MainView、DetailPanel、JsonPreview、ReferencesModal），以保证可读性与后续演进。
