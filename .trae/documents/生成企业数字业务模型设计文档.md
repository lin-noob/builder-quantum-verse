## 关联总览（语义与边）

* 锚点：Entities 是所有模块的锚点；其他 6 模块通过明确字段建立“指向边”。

* 关系边定义：

  * Capabilities → Entities（input\_entities、output\_entities）、→ Lifecycle（allowed\_states / trigger）

  * Rules → applies\_to: entity/capability/state（若为 state 需携带 entity+state）

  * Lifecycle → Transitions.trigger: Capability.id（每条边绑定能力触发）

  * Events → source: entity | state\_change | rule\_violation（可反向指向 Lifecycle 边或 Rule）

  * Processes → start\_event: Event.id；steps\[]: capability/rule\_check；end\_states\[]: Lifecycle.states

  * Responsibility → target: entity/capability/process（携带 ref\_id）

* 页面统一以“引用关系”显示：每个资产卡和抽屉右侧显示被引用次数与引用列表；支持点击跳转到对应模块并定位。

## 页面呈现（向导右侧内容）

* 顶部 Chips：当前模块显示关键信息并给出跨模块入口（例如在 Capabilities 显示所关联 Entities Chips，点击切换到 Entities 并高亮）。

* 右侧“上下文面板”：在抽屉右侧显示“相关模块”卡片（例如在 Rule 抽屉：显示 被约束实体/能力/状态、可衍生事件），全为可点击跳转。

* 迷你关系图：在“引用关系总览”弹窗中用 React Flow 渲染跨模块小图，节点为 7 大模块资产，边为上述关系；支持筛选与高亮当前资产。

* 列表列/徽标：在资产表中用徽标/计数列显示关联概览（如 Capabilities 列展示输入/输出实体数量与被 Lifecycle 使用的次数）。

## 新建时的关联交互（上下文驱动）

* Entities → 新建能力/规则/事件入口：

  * 能力：从对象上下文新建，必须选择 input\_entities/output\_entities，默认锁定当前对象；允许选择 allowed\_states（来自 Lifecycle.states）。

  * 规则：在对象上下文新建默认 applies\_to=entity；若选择 state，需选择 entity + state；若选择 capability，需选择能力。

  * 事件：来源选择 state\_change（需选择 entity + from/to）、rule\_violation（需选择 rule）、entity\_change（关键字段）。

* Lifecycle（图边）→ 新建：

  * 新增边时强制选择触发能力（Capability.id）；

  * 边面板可“附加规则检查”（将 Rule 以 rule\_check 方式附着到流程或边）；

  * 在状态/边上“生成事件”（source=state\_change），直接打开事件表单并预填 entity、from/to。

* Capabilities → 新建规则/事件：

  * 规则附着：默认 applies\_to=capability 并预填 ref=当前能力；

  * 允许选择 allowed\_states（从关联实体的 Lifecycle.states 下拉）；

  * 可一键“生成事件”用于能力执行完成（source=entity\_change 或 state\_change）。

* Rules → 新建事件/流程：

  * 在规则面板中“生成事件 source=rule\_violation”，预填 rule\_id；

  * 在流程中添加 rule\_check 步骤，选择 Rule。

* Events → 新建流程：

  * 新建流程时默认 start\_event=当前事件；steps 通过选择 capability/rule\_check；end\_states 下拉来自事件关联实体的 Lifecycle；

  * 事件表单中显示“可触发流程”列表，支持“新增流程”入口。

* Responsibility → 新建：

  * 必选 target（entity/capability/process）与 ref\_id（可搜索选择）；

  * 升级策略模板（条件/时限/升级至）在 Responsibility 表单中一次完成。

## 校验与“正确答案范围”

* 必填校验：

  * 能力必须选择至少 1 个 input/output\_entity；

  * 生命周期边必须选择 trigger 能力；

  * 规则在 state 模式必须携带 entity+state；

  * 流程必须有 start\_event、至少 1 步、end\_states 不为空；

* 约束校验：

  * 能力 allowed\_states 必须存在于关联实体 Lifecycle.states；

  * 流程 steps 中的 capability 若被规则 Blocking 拦截，给出提示并允许保存为草案（需审批）。

* 关联完整性：所有 ref\_id 必须有效（下拉选择/可搜索），支持“快速新建”缺失项并回填。

## 抽屉信息结构（体现关联）

* Entities：显示 attributes/relationships；“引用关系”列出 Capabilities、Rules（applies\_to=entity/state）、Lifecycle（states/edges）、Events（source=entity/state\_change）与 Processes（涉及该实体的 end\_states）。

* Capabilities：显示 input/output 实体、allowed\_states、side\_effects；关联：Lifecycle 边使用次数、附着 Rules、生成 Events、出现在 Processes.steps。

* Rules：显示 applies\_to 范围、表达式、violation\_action、override\_policy；关联：被 Events 用作 rule\_violation、被 Processes.rule\_check 引用。

* Lifecycle：显示 states/edges 列表，edge.trigger=Capability；关联：Events 来源为 state\_change；Processes 的 end\_states 映射。

* Events：显示 source、检测类型、订阅语义；关联：作为 Processes.start\_event；可回跳到来源 Rule/Lifecycle。

* Responsibility：显示 target/ref\_id 与升级策略；关联：在对应目标的抽屉中以“责任”小卡展示。

* Processes：显示 start\_event、steps（capability/rule\_check）、end\_states；关联：指向 Events/Lifecycle/Capabilities/Rules 的关系明细。

* 所有关联选择都提供“正确答案范围”，并通过校验保证引用完整性。
